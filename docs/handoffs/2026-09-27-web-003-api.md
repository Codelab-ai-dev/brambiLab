## Objetivo y alcance de este PR
Primera de tres entregas de WEB-003: modelo de datos, validación del documento canónico v1 y API privada de contenido, traducciones, revisiones y taxonomía. Editor/Markdown (parte 2) y panel/autoguardado/e2e (parte 3) siguen pendientes.

## Decisiones
- **Formato canónico propio** (web-v1.md §7.1), no el JSON de Tiptap. Un adaptador en el cliente (parte 2) convierte en ambos sentidos. Go valida de forma estricta: nodos, marcas y atributos conocidos, enlaces seguros y límites de 1 MiB, profundidad 32, 20 000 nodos y 200 000 caracteres.
- **Guardado** (web-v1.md §6.2), en este orden:
  1. repetición idempotente;
  2. contenido archivado;
  3. `expected_version`, con 409 y `current_version`;
  4. snapshot idéntico, con 200 `created:false`;
  5. taxonomía existente;
  6. inserción y avance atómico de `latest_version`.
- **Garantías en PostgreSQL:**
  - FK compuesta: un log sólo puede apuntar a un proyecto.
  - Triggers: tipo y padre inmutables; revisiones y etiquetas de revisión sin UPDATE ni DELETE.
  - FK compuesta: `published_revision_id` sólo acepta revisiones de la misma traducción.
- Una categoría opcional y hasta 20 etiquetas por revisión, ligadas a la revisión. Medios (`image`, `video`, `download`) definidos pero rechazados con `media_not_available` hasta WEB-004.
- Contenido archivado: sólo lectura; no se puede archivar si está publicado (409 `published_content`).
